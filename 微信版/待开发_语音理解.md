# 待开发：微信语音消息理解（SILK → WAV → ASR）

**状态：设计完成，尚未实现。** 随时可按本文件继续开发。

---

## 一、目标

收到语音消息时，转成文字后像普通文本一样理解并回复——**记忆、用户画像、情绪状态、RAG 全部照常生效**（与图片理解的模式完全一致）。

## 二、关键事实（已核实，勿重复踩坑）

1. **语音消息类型标识**：`msg.type == 'voice'`
   （对应 `wechatauto/msgs/mtype.py` 的 `VoiceMessage.type = 'voice'`；`MSG_TYPE_NAMES[34] = "语音"`）

2. **库可以直接下载语音**：`MediaDownloader.download_media(who, local_id, save_dir)`
   - `local_type == 34` 时分派到 `download_voice()`（`wechatauto/media.py`）
   - 数据来源：`media_*.db` 的 `VoiceInfo.voice_data`
   - **输出格式是 `.silk`（微信专用编码，不能直接播放/识别）**
   - 前置条件：该消息存在 `server_id`，且语音分片存在于某个 `media_*.db`

3. **DeepSeek 不支持音频输入**
   官方文档（api-docs.deepseek.com/zh-cn/guides/vision）明确：`deepseek-flash` 仅支持图像理解，
   图片格式限 JPEG / PNG / GIF / WebP。**没有音频接口** → 必须自建 ASR 环节。

4. **`pip install pilk` 在本机失败**
   ```
   error: Microsoft Visual C++ 14.0 or greater is required.
   ```
   本机没有 MSVC 编译器（与之前 winsdk 编译失败同因）。解决方式二选一：
   - **推荐**：到 https://github.com/foyoux/pilk/releases 下载文件名含 **`cp312`** 与 **`win_amd64`** 的预编译 wheel，再 `venv\Scripts\python.exe -m pip install 下载的文件.whl`（免编译）
   - 备选：到 https://github.com/kn007/silk-v3-decoder 的 `windows/` 目录取预编译 `silk_v3_decoder.exe`，用 subprocess 调用

## 三、设计：三步流水线

```
收到语音消息（msg.type == 'voice'）
   ↓ ① MediaDownloader.download_media(who, local_id, MEDIA_DIR)  →  得到 xxx.silk
   ↓ ② SILK → WAV（16kHz 单声道 16bit）
   ↓ ③ ASR：语音转文字
   ↓ text = f"[对方发来一条语音，说的是：{transcript}]"
   ↓ 走原有流程（检索知识库 + 画像 + 状态 → 调 deepseek-flash → 分条发送 …）
```

## 四、ASR 选型对比

| 方案 | 成本 | 说明 |
| --- | --- | --- |
| **硅基流动 SenseVoice-Small** | 免费额度 | OpenAI 兼容 `/audio/transcriptions`，中文识别好，只需注册拿 key，无需下模型 |
| 本地 faster-whisper | 免费离线 | 不用 key，但要下模型（200MB~1GB），可能再次遇到 HuggingFace 下载问题 |
| 腾讯云 / 讯飞 ASR | 有免费额度 | **支持 SILK 直传**（可省掉第 ② 步解码），但签名鉴权接入较麻烦 |

**推荐组合：pilk 预编译 wheel + 硅基流动 SenseVoice**（都不需要编译、不需要显卡）。

## 七、预期限制（实现后同样存在）

1. 语音必须已经存在于本地 `media_*.db`（微信里收到过且未被清理）
2. ASR 有延迟（在线接口约 1~3 秒），会叠加在现有回复延迟上
3. 微信语音气泡仍发不出去（回复只能是文字/音频文件/表情包）
4. 长语音转写成本更高，可考虑只转写前 N 秒或按时长过滤
