# 规划与反思：实现记录与调优日志

> 记录「Plan → Act → Reflect」能力的完整实现与调优过程：**两次误判根因排查 → 发现评测方法学缺陷 → 升级评测 → 三配置对照**。
> 所有数字均可用文末命令复现。

---

## 一、设计：三种模式按需触发

简单闲聊不增加任何额外调用，只有复杂请求才付出额外开销。

```
用户消息
  ├─ ① Plan（规划）  规则判定复杂度 → 生成 2~5 步执行计划 → 注入上下文
  ├─ ② Act（执行）   模型自主调用工具，结果回喂后继续推理（多轮循环）
  └─ ③ Reflect（反思）风险检测 → 必要时质检草稿 → 未通过则修订
```

| 触发条件 | 判定方式 | 成本 |
| --- | --- | --- |
| Plan | 规则：含「先/然后/再/顺便/对比…」或一句话两个问号，且长度 ≥15 字 | +1 次调用（仅复杂请求） |
| Reflect | **风险触发**（见第四节）或 5% 抽样 | +1~2 次调用（仅高风险轮次） |

规则判定实测准确（`python 规划.py` 自测）：

| 输入 | 判定 |
| --- | --- |
| 你好呀 / 现在几点了？ / 帮我看看北京天气 | 直接回答 |
| 先查一下专业版价格，再帮我算买三年一共多少钱 | **需要规划** |
| 现在几点？顺便算一下 25 乘以 4 | **需要规划** |

规划质量示例（真实输出）：

```
🧭 执行计划：
   1. 用价格查询工具获取专业版的单价（每期/每年费用）
   2. 用计算工具将专业版单价乘以 3，得出三年总费用
```

## 二、第一轮：首版反思是负收益

| 指标 | 无规划（基线） | 开规划+反思（首版） |
| --- | --- | --- |
| 任务达成率 | 95.7% | **87.0%** ↓8.7pp |
| 平均延迟 | 1.70s | **2.72s** ↑60% |

**通过日志定位到两次误判：**

### 误判 1：质检依据被截断

```
🔍 质检未通过：工具结果未提供客服邮箱，草稿编造了 support@example.com。
```
但评测知识库里**确实有**这条信息 —— 传给质检员的工具结果被截断到 **120 字符**，它看不到真实内容就判"编造"，修订时**把正确答案删掉了**。
**修复**：工具结果保留长度 120 → 1000 字符。

### 误判 2：质检依据范围过窄

```
🔍 质检未通过：工具结果为空（本轮未调用工具），草稿却给出"专业版99元""三年297元"，属编造。
```
但答案来自**同一会话中前几轮的工具结果**（模型记住了，本轮无需再调工具）；而质检员只能看到「本轮工具结果」。
**修复**：
1. 新增 `_evidence()` —— 把「系统注入的参考资料 + 本轮工具结果」一并交给质检员
2. 质检提示词改为**保守判定**：只有"依据中完全不存在的信息被当成事实写出"才判 FAIL，**不确定一律 PASS**
3. 修订提示词强调：依据充分时保留原有正确信息，不要因保守而删掉有出处的关键数字

### 附带修复：函数误删导致全链路异常

重构 `_evidence()` 时误删 `_tools_digest()`，反思分支抛 `NameError`，被 `ask_bot` 的兜底捕获后返回错误串 —— 达成率一度跌到 34.8%、token 掉到 460/轮，**接口却没有任何报错**。

> **教训**：兜底的 `try/except` 会把逻辑错误伪装成"回答质量差"，必须靠评测指标而非单条观感发现问题。

## 三、第二轮：怀疑评测本身不严谨

修复后重跑，达成率 91.3%（vs 基线 95.7%），仍是负收益。但进一步检查发现**评测方法本身有缺陷**：

| 问题 | 影响 |
| --- | --- |
| **用例不隔离**：23 条用例跑在同一会话里 | 前一条的工具结果进入历史，影响后一条的工具决策（既造成误判 2，也让用例互相污染） |
| **单次评测方差大**：模型有随机性 | 基线在两次不同运行中分别跑出 95.7% 与 100%（±8.7pp），**单次差异可能大于策略差异** |

**方法学修复**（`评测.py`）：
1. **用例隔离**（默认开启）：每条用例使用独立会话，消除历史串扰
2. **重复实验** `--repeat=N`：多轮取 **均值 ± 标准差**，区分真实差异与噪声
3. **新增指标**：无需工具时误调率、质检触发次数，让成本可度量

---

## 四、第三轮：策略改进 —— 从"每轮质检"到"风险触发"

原策略"用过工具就质检"过于粗暴（成本高、易误伤）。改为**只在检测到风险信号时质检**：

```python
def detect_risk(draft, evidence, tool_calls, tool_errors, question):
    """三类风险信号"""
    ① 数字无出处    —— 草稿里的数字在依据中找不到（最可能算错/编造）
    ② 工具异常      —— 有工具失败/返回空，模型却照常作答
    ③ 该查不查      —— 事实型提问（多少钱/几点/邮箱…）但未调用任何工具
```

**零成本本地检查**：数字一致性用正则抽取比对，不消耗任何 API 调用。

自测（`python 规划.py`）：

| 草稿 | 依据 | 判定 |
| --- | --- | --- |
| 专业版 99 元一年 | 含 99 | 正常 |
| 三年一共 297 元 | 不含 297 | **风险**（数字无出处） |
| 客服邮箱是 support@x.com | 空 + 未调工具 | **风险**（该查不查） |
| 今天天气不错呀 | — | 正常 |
| 查询失败，我也不知道 | 有工具异常 | **风险**（工具异常） |

## 五、三配置对照结果（23 条 × 2 轮，用例隔离）

| 指标 | A) 基线（无规划无反思） | B) 反思全触发（旧策略） | C) 反思风险触发（新策略） |
| --- | --- | --- | --- |
| 任务达成率 | **100.0%** ± 0.0 | 95.7% ± 4.3 | 97.8% ± 2.2 |
| 工具调用正确率 | 91.3% ± 8.7 | 95.7% ± 4.3 | 95.7% ± 4.3 |
| 无需工具误调率 | 0% | 0% | 0% |
| 平均延迟 | **1.50s** ± 0.0 | 2.91s ± 0.3 | **2.27s** ± 0.1 |
| 平均 token/轮 | **1872** | 1966 | 1974 |
| 规划触发 | 0 | 5 | 5 |
| **质检触发** | 0 | **20 次** | **4 次（−80%）** |
| 反思修订 | 0 | 2 | 0 |

### 结论（诚实版）

1. **风险触发策略达成目标**：质检调用从 20 次降到 4 次（**−80%**），平均延迟从 2.91s 降到 2.27s（**−22%**），质量指标未下降
2. **反思的质量收益在当前规模下无法确认**：基线与风险触发的达成率差异（100% vs 97.8%）落在标准差范围内（±2.2），**不能声称反思提升了质量**
3. **工具调用正确率的差异同样不可信**：基线两轮分别为 100% / 82.6%（±8.7），与反思组的差异完全在噪声内
4. **确认的收益是"成本可控"**：风险触发使反思开销从"每轮有工具就付费"变成"按风险付费"，17% 的轮次触发质检

> **方法论收获**：若没有升级评测方法（隔离 + 重复 + 标准差），我会得出两个错误结论 ——
> ① "反思是负收益"（其实是方差）；② "反思提升工具调用质量 +4.4pp"（同样是方差）。

## 六、当前状态与后续

| 项 | 状态 |
| --- | --- |
| Plan（规则触发 + 计划注入） | ✅ 稳定可用 |
| Act（工具循环 + 异常追踪） | ✅ 稳定可用 |
| Reflect（风险触发 + 保守判定 + 修订） | ✅ 功能可用，质量收益待更大规模评测确认 |
| 评测方法学（隔离 / 重复 / 成本指标） | ✅ 已升级 |
| 已知良性误报 | 模型写出中间计算步骤（如 `128×37=4736`）会被判"数字无出处"，触发一次多余质检（质检会 PASS），代价约 +0.5s |

**后续待办（按优先级）**
1. **评测集扩容到 50~100 条**，并加入「人设一致性（OOC）」「多轮记忆一致性」类别 —— 当前规模不足以判定反思的真实收益
2. **多轮对话用例**：现有用例都是单轮，未覆盖"依赖历史的多轮任务"这一反思最可能发挥价值的场景
3. **降低误报**：数字检查可增加"中间计算步骤"豁免（例如允许草稿中的乘法中间值）
4. **反思分级**：当前是二元 PASS/FAIL，可引入"轻微问题可接受"档位，减少无谓修订
