# 规划与反思：实现记录与调优日志

> 本文记录「Plan → Act → Reflect」能力的实现过程、实测数据，以及**两次真实回归的根因排查**。
> 状态：功能已实现并接入主流程；反思模块仍在调优，最终数值待补测（见文末「待办」）。

---

## 一、设计：三种模式按需触发

简单闲聊不增加任何额外调用，只有复杂请求才付出额外开销。

```
用户消息
  ├─ ① Plan（规划）  规则判定复杂度 → 生成 2~5 步执行计划 → 注入上下文
  ├─ ② Act（执行）   模型自主调用工具，结果回喂后继续推理（多轮循环）
  └─ ③ Reflect（反思）质检草稿 → 未通过则修订
```

| 触发条件 | 判定方式 | 成本 |
| --- | --- | --- |
| Plan | 规则：含「先/然后/再/顺便/对比…」或一句话两个问号，且长度 ≥15 字 | +1 次调用（仅复杂请求） |
| Reflect | 用过工具或做过规划 → 必查；普通回答 → 15% 抽样 | +1~2 次调用 |

实测规则判定准确（`规划.py` 自测）：

| 输入 | 判定 |
| --- | --- |
| 你好呀 | 直接回答 |
| 现在几点了？ | 直接回答 |
| 先查一下专业版价格，再帮我算买三年一共多少钱 | **需要规划** |
| 现在几点？顺便算一下 25 乘以 4 | **需要规划** |
| 帮我看看北京天气怎么样 | 直接回答 |

规划质量示例（真实输出）：

```
🧭 执行计划：
   1. 用价格查询工具获取专业版的单价（每期/每年费用）
   2. 用计算工具将专业版单价乘以 3，得出三年总费用
```

## 二、实测数据（23 条用例，Agentic RAG 模式）

| 指标 | 无规划（基线） | 开规划+反思（首版） |
| --- | --- | --- |
| 任务达成率 | **95.7%** (22/23) | **87.0%** (20/23) ↓8.7pp |
| 工具调用正确率 | 82.6% | 82.6% |
| 多步任务达成率 | 100% (3/3) | 100% (3/3) |
| 平均延迟 | 1.70s | **2.72s** ↑60% |
| 平均 token/轮 | 2110 | 2111 |
| 规划触发 / 反思修订 | 0 / 0 | 5 / 3 |

**结论：首版反思机制是负收益——准确率下降 8.7pp、延迟涨 60%。** 通过日志定位到两次误判，详见下节。

## 三、两次回归的根因与修复

### 回归 1：质检依据被截断，把正确答案判成「编造」

**现象**（日志）：
```
🔍 质检未通过：工具结果未提供客服邮箱，草稿编造了 support@example.com 和工作时间。
🔍 质检未通过：'团队版 399 含 5 个席位'在工具结果中并无依据，属于编造信息。
```
但评测知识库里**确实有**这些信息。

**根因**：传给质检员的工具结果被截断到 120 字符，质检员看不到真实检索内容 → 判定为编造 → 修订时删掉了正确信息。

**修复**：工具结果保留长度 120 → 1000 字符。

### 回归 2：质检依据范围过窄，误判「历史上下文」为编造

**现象**（修复 1 之后）：
```
🔍 质检未通过：工具结果为空（本轮未调用工具），草稿却直接给出"专业版99元""三年297元"，属编造。
```
但答案来自**同一会话中前几轮的工具结果**（模型记住了，因此本轮无需再调工具）。

**根因**：质检员只能看到「本轮工具结果」，而模型的作答依据还包括【系统注入的参考资料】与【对话历史】。

**修复**：
1. 新增 `_evidence()`——把「系统提示中的参考资料 + 本轮工具结果」一起交给质检员
2. 质检提示词改为**保守判定**：只有发现"依据中完全不存在的信息被当成事实写出"才判 FAIL，不确定一律 PASS
3. 修订提示词强调：依据充分时保留原有正确信息，不要因保守而删掉有出处的关键数字

### 附带修复：函数误删导致全链路异常

重构 `_evidence()` 时误删了 `_tools_digest()`，导致反思分支抛 `NameError`，被 `ask_bot` 的兜底捕获后返回错误串，任务达成率一度跌到 34.8%、token 掉到 460/轮。
**教训**：兜底 try/except 会把"逻辑错误"伪装成"回答质量差"，必须用评测指标而非单条观感来发现——这正是本套评测体系的价值。

## 四、当前状态与待办

**已可用**：Plan（规则触发 + 计划注入）与 Act（工具循环）已稳定工作，规划质量良好。

**待补测**：两处修复后 `--plan=on` 的完整数值尚未跑完（最后一轮评测被中断）。预计需要：

```powershell
venv\Scripts\python.exe 评测.py --mode=tool --plan=off   # 基线
venv\Scripts\python.exe 评测.py --mode=tool --plan=on    # 对照
```

**待优化方向**：
1. 若修复后仍为负收益，考虑：反思只在「工具结果为空但回答含具体数字」这类高风险场景触发
2. 把「是否值得修订」也交给模型判断（当前是二元 PASS/FAIL，缺少"轻微问题可接受"的档位）
3. 反思增加"依据一致性"检查的具体化：要求质检员**引用依据原文**再判定，减少主观误判
4. 评测集扩容到 50~100 条，覆盖更多多步任务与边界场景
